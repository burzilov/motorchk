# Мультиязычность и хуки сайта

С 0.4.0 ядро умеет работать на нескольких языках, но **само языки не включает**: списком языков,
адресами (`/en/…`), переключателем и словарями занимается плагин (например, `i18n`). Без такого
плагина сайт работает как раньше — на одном языке, байт в байт как 0.3.

Точки расширения общие — ими может пользоваться любой плагин:

| Что | Где | Зачем |
|-----|-----|-------|
| Службы | `provides` в `plugin.json`, `provide()` / `service()` | плагины пользуются объектами друг друга |
| Событие `request` | `on('request', …)` | до маршрутизации: переписать путь, задать язык, ответить редиректом |
| Фильтр `url` | `filter('url', …)` | адреса внутри сайта: меню, `publicUrl()`, hreflang, `SiteLocale::url()` |
| Фильтр `menu` | `filter('menu', …)` | все меню страницы (`$menus`) перед шаблоном |
| Фильтр `head` | `filter('head', …)` | HTML в `<head>` (через `site-chrome.php`) |
| Фильтр `output` | `filter('output', …)` | готовый HTML страницы (Markdown и страницы плагинов) |
| Язык | `SiteLocale`, `LocaleProvider`, служба `i18n` | текущий/основной язык, `<html lang>`, hreflang, переводы страниц |

Хуки работают **только на сайте**: админка (`/admin-panel/…`) и статика `/plugin-assets/…` их не
вызывают.

## Хуки

Плагин перечисляет хуки в `plugin.json` — так ядро знает, какие плагины загрузить, не выполняя код
остальных:

```json
{ "id": "i18n", "provides": ["i18n"], "hooks": ["request", "url", "menu", "head", "output"] }
```

Регистрация — в точке входа. Хук, не объявленный в `hooks`, — ошибка загрузки плагина
(видна на «Системе»).

```php
return static function (PluginContext $plugin): void {
    $plugin->on('request', static function (SiteRequest $request): void { /* … */ });
    $plugin->filter('url', static fn(string $url, array $context): string => $url, 10);
};
```

- Порядок: `priority` по возрастанию (по умолчанию 10), затем порядок загрузки плагинов (по алфавиту) и регистрации.
- Исключение в обработчике пишется в `error_log`, остальные обработчики выполняются.
- Фильтр должен вернуть значение **того же типа**; иначе результат игнорируется (ошибка в `error_log`).

### `request` — до маршрутизации

`function (SiteRequest $request): void` — один раз на публичный запрос, до форм (`/api/forms/submit`),
префиксов плагинов и Markdown-страниц. Переписанный путь видят все.

| Метод `SiteRequest` | |
|---|---|
| `method()`, `path()`, `originalPath()` | метод, путь для маршрутизации, исходный путь |
| `setPath('/about')` | новый путь (начинается с одного `/`) |
| `locale()`, `setLocale('en')` | язык запроса; `setLocale()` принимает только языки службы `i18n` (иначе `false`) |
| `query()`, `cookie()`, `header()` | `$_GET`, `$_COOKIE`, заголовок запроса |
| `redirect('/en/', 302)` | ответить редиректом внутри сайта; дальше ядро запрос не обрабатывает |
| `markHandled()` | ответ уже отправлен хуком |

### `url` — адреса внутри сайта

`function (string $url, array $context): string`, `$context = ['locale' => 'en', 'source' => 'menu' | 'plugin' | 'theme' | 'alternate' | 'canonical']`.
`locale` — язык, **на который** нужна ссылка (обычно текущий). Ядро вызывает фильтр для внутренних
ссылок меню (не для внешних и не для якорей `#…`), в `PluginContext::publicUrl()`, для hreflang и
canonical и в `SiteLocale::url('/about')` — хелпере для тем.

### `menu`, `head`, `output`

- `menu`: `function (array $menus, array $context): array` — все меню (`['main' => [...], 'footer' => [...]]`) после фильтра `url`.
- `head`: `function (string $html, array $context): string` — строка, которую `site-chrome.php` выводит после CSS ядра (строки с отступом 4 пробела и `\n`).
- `output`: `function (string $html, array $context): string` — весь HTML страницы. Пока такого фильтра нет и служба `i18n` не активна, ядро страницу не буферизует.

`$context` у `menu`, `head`, `output`: `slug`, `locale`, `content_locale`, `preview` (у `output` ещё `status`).

## Службы

```json
{ "id": "i18n", "provides": ["i18n"] }
```

```php
// плагин i18n, точка входа
$plugin->provide('i18n', new I18n\Service($plugin));

// любой другой плагин, в обработчике маршрута
$i18n = $plugin->service('i18n'); // объект или null
```

- Имя службы — `^[a-z0-9-]+$`, объявляется в `provides`. Две службы с одним именем — побеждает плагин, первый по алфавиту.
- Владелец загружается при первом `service()`. Если его нет, он сломан или не вызвал `provide()` — `null`; проверяйте это.
- Вызывайте `service()` в обработчиках, а не в точке входа — тогда порядок загрузки плагинов не важен.

## Язык

### Служба `i18n` и `LocaleProvider`

Ядро считает сайт многоязычным, если служба `i18n` реализует интерфейс ядра `LocaleProvider`:

```php
interface LocaleProvider
{
    public function locales(): array;       // ['ru', 'en'] — включая основной
    public function defaultLocale(): string; // 'ru'
}
```

Коды языков — `^[a-z]{2,3}(-[a-z0-9]{2,8})?$` в нижнем регистре (`ru`, `en`, `pt-br`); остальные
ядро отбрасывает. Как язык попадает в адрес, решает плагин: событием `request` он вызывает
`setLocale()` и убирает префикс, фильтром `url` — добавляет его к ссылкам.

### `SiteLocale` (ядро)

| | |
|---|---|
| `SiteLocale::current()` | язык запроса (без службы — `ru`) |
| `SiteLocale::default()`, `locales()`, `isActive()`, `isDefault()` | основной язык, все языки, есть ли служба, основной ли текущий |
| `SiteLocale::url('/about', 'en')` | адрес на языке через фильтр `url` |
| `SiteLocale::provider()` | служба `i18n` или `null` |

В плагине то же через `PluginContext`: `locale()`, `defaultLocale()`, `locales()`,
`localized(['ru' => 'Ловушка', 'en' => 'Catcher'])` (текущий язык → основной → первое непустое).

### Переменные шаблона темы

| Переменная | |
|---|---|
| `$locale` | язык запроса (интерфейс: меню, переключатель) |
| `$defaultLocale` | основной язык |
| `$contentLocale` | язык содержимого страницы: при показе оригинала вместо перевода — основной |
| `$alternates` | `['ru' => '/about', 'en' => '/en/about']` — переводы страницы (пусто, если перевода нет) |
| `$i18n` | служба `i18n` или `null` (например, `<?= $i18n?->switcher() ?>`, если плагин это умеет) |

`<html lang>`: тема-пример пишет `<html lang="<?= htmlspecialchars($contentLocale ?? 'ru') ?>">`.
Темы, где по-прежнему `<html lang="ru">`, менять не обязательно: пока служба `i18n` активна, ядро
само подставляет `$contentLocale` в атрибут `lang` первого `<html>` страницы.

### hreflang и canonical

Ядро выводит их в `<head>` через `includes/views/site-chrome.php` (его подключают все темы), только
пока служба `i18n` активна:

- `<link rel="alternate" hreflang="xx" href="…">` для каждого языка, на котором **есть** опубликованный перевод страницы, и `hreflang="x-default"` на основной язык — только если языков хотя бы два;
- на странице без перевода (показан оригинал) — `<link rel="canonical">` на оригинал, без hreflang;
- адреса абсолютные: схема и `Host` текущего запроса.

Страницы плагинов получают hreflang, если передают `alternates` в `renderPublic()`.

## Переводы Markdown-страниц

**Файл перевода лежит рядом с оригиналом, с кодом языка перед `.md`:**

```text
content/
├── index.md          → /
├── index.en.md       → /en/
├── about.md          → /about
├── about.en.md       → /en/about
├── about/team.md     → /about/team
└── about/team.en.md  → /en/about/team
```

- Формат — как у обычной страницы (front matter + блоки). Из перевода берутся `title`, `description`, `og_*`, `published` и блоки; адрес и место в дереве — у оригинала.
- Перевод показывается, только если оригинал существует и опубликован (снятая с публикации страница скрыта на всех языках) и сам перевод не снят с публикации.
- Нет перевода — по адресу `/en/about` показывается оригинал: `$contentLocale = 'ru'`, `<html lang="ru">`, canonical на `/about`, интерфейс (меню, переключатель) — на языке запроса.
- Подпись пункта меню без `label` берётся из `title` перевода. Пункты с явным `label` переводит плагин (фильтр `menu`).
- Пока служба `i18n` активна, файлы `*.{язык}.md` — не страницы: их нет в дереве и в списке страниц админки, адрес `/about.en` даёт 404. Без службы это обычные файлы (как в 0.3): `/about.en` откроется как страница. Slug в админке не может содержать точку, поэтому с её страницами переводы не пересекаются.
- Переводы правятся файлами (FTP, git): редактора переводов в админке нет. Кеш переводов сверяется с временем изменения файла, сбрасывать его не нужно.
- Inline-edit работает только на основном языке: он сохраняет оригинал.
- Переименование и удаление страницы в админке переводы не трогают — переименуйте/удалите `*.en.md` вручную.

## Без службы i18n

Без папки `plugins/` и без плагина со службой `i18n` ядро не меняет ни адреса, ни разметку: нет
буферизации страниц, нет hreflang, `site-chrome.php` выводит одну строку, `<html lang>` — как в теме.
Это проверяет `php tests/i18n.php` (сравнение ответов «без плагинов» и «с плагинами без i18n»).
