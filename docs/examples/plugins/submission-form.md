# Вкладка заявок из плагина

Пример вызова `submissions()->registerForm()`. Это не отдельный режим ядра и не плагин из этого репозитория: тот же API, что у любой формы. Ниже — фрагмент, который нужен плагину вроде конфигуратора, если все изделия должны попасть в **одну** вкладку, а серверное поле «Представлена модель» не должно быть столбцом по умолчанию.

Ядро не знает слов «изделие», «офис» и «модель». Оно показывает ключи, которые плагин перечислил, и значения из `payload` как они записаны.

## plugin.json

```json
{
    "id": "miklin-customizer",
    "name": "Конфигуратор",
    "version": "1.0.0",
    "core": ">=0.7.0",
    "submission_forms": true
}
```

`"submission_forms": true` обязателен: без него страница «Заявки» не загружает плагин, а `registerForm()` бросает `LogicException`.

`"core": ">=0.7.0"` — метод появляется в минорном выпуске 0.7.0. Пока в репозитории ядра `VERSION` ещё `0.6.10`, такое ограничение **не пустит** плагин (официальный 0.6.10 этого метода тоже не содержит). Не ставьте `>=0.6.10`: его удовлетворит и уже выпущенный 0.6.10 без `registerForm`, и точка входа упадёт. Публикуйте плагин вместе с ядром 0.7.0. Ограничение `^0.6` на 0.7.0 тоже не подойдёт: для `0.x` минорная версия считается несовместимой. Плагины, которые `registerForm` не вызывают, менять не нужно (`>=0.5.0` по-прежнему загружается).

## Точка входа

Один id `customizer-order` на все изделия. Отдельные вкладки на 35 товаров не появятся, пока `create()` пишет этот же id.

```php
<?php

return static function (PluginContext $plugin): void {
    $plugin->submissions()->registerForm('customizer-order', 'Заказы конфигуратора', [
        'item' => 'Изделие',
        'product_model' => 'Модель',
        'name' => 'Заказчик',
        'email' => 'Email',
        'office' => 'Исполнитель',
    ]);
};
```

Порядок ключей — порядок столбцов между «Дата» и «Почта». Пока администратор не сохранил свою настройку, таблица именно такая. Сброс в админке возвращает этот список.

Ключ столбца: с буквы, дальше латиница, цифры, `_` и `-`, не длиннее 64 символов. Подпись столбца — до 80 символов.

Ключ серверного поля «Представлена модель» в список **не входит**. Если в заявке он называется `model`, просто не регистрируйте `model`. Выбранная модель остаётся `product_model`. Ядро само не отличает эти ключи: если не зарегистрировать нужный, столбца не будет; если перепутать имя, столбца тоже не будет. Карточка одной заявки по-прежнему показывает все поля `payload`, в том числе этот ключ: таблица и карточка — разные места.

Поле, которое есть в заявках, но не передано в `registerForm`, попадает в блок «Столбцы» **выключенным**. Администратор может включить его сам. Скрыть ключ так, чтобы его нельзя было включить, этот API не умеет.

## Что класть в заявку

`create()` вызывается как раньше. В `office` должна лежать уже готовая подпись офиса. Ядро не ищет офис по id и не подставляет email. Что записано в `payload['office']`, то и стоит в ячейке, в том числе у старых заявок: файлы заявок ядро не переписывает.

```php
$payload = [
    'item' => $itemName,
    'product_model' => $selectedModel,
    'name' => $customerName,
    'email' => $customerEmail,
    'office' => $officeName,
    // ключ «Представлена модель» можно по-прежнему сохранять в payload,
    // но не передавайте его в registerForm(), если он не нужен в таблице.
];

$contract = [
    ['name' => 'item', 'type' => 'text', 'required' => true, 'label' => 'Изделие'],
    ['name' => 'product_model', 'type' => 'text', 'required' => true, 'label' => 'Модель'],
    ['name' => 'name', 'type' => 'text', 'required' => true, 'label' => 'Заказчик'],
    ['name' => 'email', 'type' => 'email', 'required' => true, 'label' => 'Email'],
    ['name' => 'office', 'type' => 'text', 'required' => true, 'label' => 'Исполнитель'],
];

$sub = $plugin->submissions()->create('customizer-order', $payload, $contract, $ip);
```

Подписи в `$contract` остаются подписями карточки заявки. `registerForm` их не меняет и не записывает настройку столбцов в JSON заявки. Переименование столбца в админке меняет только заголовок таблицы.

Не создавайте `content/forms/customizer-order.yaml`, если это не публичная форма ядра. Регистрация вкладки живёт в плагине, настройка столбцов — в `content/_submission-columns.json`.

## Чего ядро не делает

- Не склеивает разные `form_id` и не прячет «лишние» вкладки, если плагин сам пишет много id.
- Не подменяет `office`, `product_model` или любое другое поле.
- Не удаляет из старых заявок ключ серверной модели. Пока он не в `registerForm`, в таблице его нет; в настройке он доступен, если встречается в сохранённых заявках.
- Не переносит переименованные заголовки таблицы на карточку заявки: там по-прежнему контракт конкретной записи.
- Не сортирует таблицу по произвольному столбцу и не ищет по нему. Порядок — новые сверху, страницы по 50, фильтр только по статусу письма.
