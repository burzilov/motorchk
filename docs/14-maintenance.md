# Режим технического обслуживания

Режим закрывает сайт от посетителей: все PHP-страницы отвечают **HTTP 503** страницей
«Закрыто на техобслуживание». Секретных ссылок и паролей нет — при включённом режиме
доступ к сайту имеет **только залогиненный администратор**: админ-панель работает как
обычно (отдельный вход `core/admin-panel/index.php`, мимо гейта), а её сессия общая
с публичной частью, поэтому после входа в админку любая страница сайта открывается.

## Включение

Страница **Система → Техническое обслуживание**: отметьте «Закрыть сайт на техобслуживание»
и нажмите «Сохранить». Состояние хранится в `content/_meta.yaml` (`maintenance_enabled`).

## Как это работает

- Проверка стоит в `Router::dispatchPublic` самым первым шагом (`Maintenance::gate`) —
  раньше SEO-файлов (`/sitemap.xml`, `/robots.txt`), языковых префиксов, хуков плагинов
  (page/request), API форм (`/api/forms/submit`) и plugin-роутов. Всё это тоже отвечает 503.
- Разрешение — одно: непустой `$_SESSION['admin_authenticated']` (сама проверка сессии
  админки), никаких отдельный ключей и cookie.
- Админ-страницу мастера входа видит любой — но пароль к ней задаётся в `.env`
  (`ADMIN_PASSWORD_HASH`), как и всегда.
- При входе админа публичные страницы работают; выход из админки снова закрывает сайт.

## Ответ страницы 503

`Maintenance::respond` отправляет: `503`, `X-Robots-Tag: noindex, nofollow`,
`Retry-After: 3600`, `Cache-Control: no-store`. Разметка самодостаточна: инлайн-CSS,
без темы, шрифтов и внешних скриптов — страница не зависит ни от контента, ни от
состояния установки. На странице есть ссылка в `/admin-panel/` для администратора.

## Что доступно при включённом режиме

| Адрес | Ответ |
|---|---|
| страницы, `/sitemap.xml`, `/api/forms/submit`, публичные роуты и `plugin-assets/…` плагинов | 503 — страница обслуживания |
| `/admin-panel/…` | как обычно (логин и вся админка) |
| `/core/assets/…` | как обычно — файлы Apache отдаёт напрямую, и они же нужны админке |
| `/themes/{имя}/assets/…`, `/media/…` | 503 при включённом режиме (см. сниппет ниже) |

## Статика Apache и сниппет для существующих установок

Apache отдаёт часть файлов напрямую, минуя PHP: `/core/assets/`, `/themes/{имя}/assets/`,
`/media/…`. PHP-гейт эти запросы не видит.

- **Новые установки** получают сниппет в корневом `.htaccess` из коробки
  (копия `core/skeleton/.htaccess`): при флаг-файле `content/.maintenance` Apache
  отвечает 503 на `/themes/{имя}/assets/` и `/media/…`.
- **Существующие установки**: корневой `.htaccess` обновление ядра не меняет — добавьте
  сниппет вручную сразу после `RewriteBase /`:

  ```apache
  # motorchk:maintenance — блокировка статики при включённом режиме обслуживания.
  RewriteCond %{DOCUMENT_ROOT}/content/.maintenance -f
  RewriteCond %{REQUEST_URI} ^/(themes/[^/]+/assets/|media/) [NC]
  RewriteRule ^ - [R=503,L]
  ```

- `/core/assets/` флаг намеренно **не блокирует**: эти же CSS/JS нужны панели
  администратора, которая обязана оставаться доступной; сам код ядра секретом не является.

Флаг-файл `content/.maintenance` создаёт и снимает ядро (`Maintenance::writeFlag`/
`removeFlag`) при сохранении галочки в админке. Даже без сниппета и флага PHP-страницы
закрыты гейтом — сниппет закрывает только перечисленную статику.
